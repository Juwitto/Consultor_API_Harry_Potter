💡 Cómo funciona fetch(), paso a paso

Lo que ocurre desde que llamas a la función hasta que pintas las tarjetas.

1

Llamada y promesa

fetch(url) lanza una petición HTTP asíncrona y devuelve de inmediato una Promise. El resto del programa sigue corriendo mientras llega la respuesta.

const respuesta = await fetch(url);
2

Objeto Response

La promesa entrega un objeto Response con el estado y las cabeceras, pero todavía sin los datos. Comprueba siempre response.ok.

if (!respuesta.ok) throw new Error(respuesta.status);
3

Leer el JSON

response.json() lee el cuerpo y lo convierte en objetos de JavaScript. También es asíncrono. Aquí obtendrás un arreglo de personajes o de hechizos.

const personajes = await respuesta.json();
4

Filtrar y mostrar

Con el arreglo en mano usa filter() y map() para quedarte con lo que importa y generar el HTML de cada tarjeta.

personajes.filter(p => p.name.includes('harry'))
5

Manejo de errores

Envuelve el flujo en try...catch para atrapar fallos de red, de CORS o una URL inaccesible, y avisa al usuario con un mensaje claro.

try { /* fetch */ } catch (e) { mostrarError(e); }

⚔️ Sintaxis: async/await frente a .then()

Hacen lo mismo por debajo. async/await se lee de arriba abajo; las promesas encadenan los pasos con .then().

✨ Opción 1: async / await 
async function obtenerGryffindor() {
  try {
    // 1. Hacer la petición HTTP
    const res = await fetch('https://hp-api.onrender.com/api/characters/house/gryffindor');

    // 2. Validar la respuesta (200-299)
    if (!res.ok) {
      throw new Error(`Error HTTP: ${res.status}`);
    }

    // 3. Convertir el cuerpo a JSON (un arreglo)
    const personajes = await res.json();

    // 4. Usar los datos
    console.log('Total:', personajes.length);
    console.log('Primero:', personajes[0].name);
  } catch (error) {
    console.error('Algo salió mal:', error.message);
  }
}
📜 Opción 2: promesas (.then / .catch) 
function obtenerGryffindorConPromesas() {
  // 1. Iniciar la petición
  fetch('https://hp-api.onrender.com/api/characters/house/gryffindor')
    .then(res => {
      // 2. Validar la respuesta
      if (!res.ok) {
        throw new Error(`Error HTTP: ${res.status}`);
      }
      // 3. Devolver la promesa del JSON
      return res.json();
    })
    .then(personajes => {
      // 4. Usar los datos
      console.log('Total:', personajes.length);
      console.log('Primero:', personajes[0].name);
    })
    .catch(error => {
      // Cualquier error de la cadena llega aquí
      console.error('Algo salió mal:', error.message);
    });
}

✅ Detalles clave y buenas prácticas

🛑

fetch no falla con un 404 o un 500

La promesa solo se rechaza ante fallos de red. Si la API responde con un error HTTP, la promesa se resuelve con response.ok = false. Revísalo tú.

⏳

Hay dos promesas en el camino

Primero esperas la respuesta de la red (fetch) y luego la lectura del cuerpo (response.json()). Ambas necesitan await o .then().

🗂️

Esta API devuelve arreglos

PokéAPI devolvía un objeto por Pokémon. Aquí cada endpoint responde con una lista, así que trabajas con filter(), map() y length.

🐢

La primera petición puede tardar

La API está en un hosting gratuito que se "duerme" si nadie la usa. La primera llamada puede tardar varios segundos: muestra siempre un estado de carga.

🔒

CORS

La API permite peticiones desde otros orígenes, por eso funciona desde tu navegador sin configurar nada. Con una API sin CORS la petición sería bloqueada.

🚫 Malas prácticas que debes evitar

🙈

Ignorar response.ok

Si llamas a .json() sin validar, un error 404 puede romper tu código más adelante con un mensaje confuso.

🔇

No tener catch

Sin captura de errores, la página se queda cargando para siempre y el usuario no sabe qué pasó.

💉

Insertar datos con innerHTML sin limpiar

Los textos de una API externa no son de fiar. Este proyecto los escapa con una función esc() antes de pintarlos.

🔁

Disparar peticiones sin control

Llamar a la API en cada tecla o varias veces seguidas la satura. Filtra en el navegador los datos que ya descargaste.
